# 零基准节点功率规划

打开 **[NodePower.ipynb](NodePower.ipynb)**，使用 `methods` 内核，依次运行五个代码块。
各节点功率直接作为非负变量 `p=(p1,p2,p3)`，单位 kW，没有基准负荷或倍率变量。
固定功率因数为 0.95；配变有功上限是 **142.5 kW**。图件研究区间为 **0–140 kW**。
模型是固定功率因数、无损有功平衡、线性平方电压降的四节点合成算例，未做 AC 潮流复核。

## 五个代码块

| 块 | 内容 |
|---|---|
| 1 | 必要模块、参数、模型和空割池；重跑此块开始新实验 |
| 2 | 构建并求解一次 MP1：固定节点功率，最小建设费 |
| 3 | 构建并求解一次 MP2：固定预算，最大总功率 |
| 4 | 对块2的候选运行 SP，展示运行变量、53 行约束及其对偶 |
| 5 | 持续推进真实 MP/SP 迭代；嵌入可旋转、可拖动回放的两张图及全部历史证据 |

块2、3使用空割池，分别给出费用下界、负荷上界；必须通过 SP 才能称为电气可行。
块5默认 `STEPS = 10`、`PAUSE = 1`。`STEPS = 1` 表示单步；改成 20 表示一次最多推进20轮。
重复运行块5会延续状态，全部查询与域证书完成后自动停止。各轮完整数值写入
`notebook_results/node_power/live/`，刷新屏幕不删除历史。

块5最后显示交互回放：“本次运行”只含已经求出的轮次；“已保存的完整实验”可直接观看完整默认过程。
支持全部轮次/仅新增割、播放/暂停、上一轮/下一轮、拖动进度和指定轮次。拖动三维图旋转，滚轮缩放；
默认四图联动，可取消联动单独查看，切换轮次保留视角。Notebook需信任输出中的JavaScript。
全部交互资源内嵌，不依赖外部网站、服务或仍在运行的内核。原始数值表位于图下可展开区域。

## 查询及电气模型

建设变量为15个二元变量，分别选择五条走廊的L/M/H线型。每条边最多一种线型，
所有节点连通且选中三条边，形成一棵树；该集合记为 $X_{\rm tree}$。
建设费为 $K(x)=c^Tx$，沿用原来的线路长度和价格。

电气运行变量是五条带符号的有功潮流及三个非根节点平方电压：

$$w=(P_{01},P_{12},P_{13},P_{02},P_{23},v_1,v_2,v_3)^T.$$

节点平衡为 $P_{01}-P_{12}-P_{13}=p_1$、$P_{12}+P_{02}-P_{23}=p_2$、
$P_{13}+P_{23}=p_3$。线路容量为 $|P_e|\le\sum_k C_kx_{e,k}$；
根电压 $v_0=1$，其他节点满足 $0.8649\le v_i\le1$；
每个选中线型满足 $v_j-v_i+a_{e,k}P_e=0$，未选线型用固定 Big-M 放松；配变限制为 $\sum_i p_i\le142.5$。
等式拆成双向不等式、全部运行变量界显式建行后，得到

$$Ww\le h+Tx+Dp,\quad W\in\mathbb R^{53\times8},\quad D\in\mathbb R^{53\times3}.$$

| 查询 | 目标与附加约束 |
|---|---|
| `min_cost`（向量 MP1） | $\min c^Tx$，固定 $p=\bar p$ |
| `max_load`（MP2） | $\max\sum_i p_i$，$c^Tx\le B$ |
| `min_cost_total`（总量 MP1） | $\min c^Tx$，$\sum_i p_i\ge L$；用于二维投影前沿 |

三个查询均保留 $x\in X_{\rm tree}$、$p\ge0$、配变上界和累计电气割。
SP 固定 $(\bar x,\bar p)$，求

$$\nu=\min_{w,\eta\ge0}\{\eta:Ww-r\eta\le h+T\bar x+D\bar p\}.$$

功率行尺度固定为142.5，电压行尺度固定为0.1351，均独立于基准负荷。其对偶是

$$\max_{\pi\ge0}-\pi^T(h+T\bar x+D\bar p),\quad W^T\pi=0,\quad r^T\pi\le1.$$

读取 Gurobi 的 `pi=-Pi`，生成全局可行性割

$$\pi^T(h+Tx+Dp)=\beta_0+\beta_x^Tx+\beta_p^Tp\ge0.$$

可行点满足该割；生成点上的割值为 $-\nu$。代码在 `build_model` 中直接写电气约束，
`build_master` 写建设约束和查询目标，`feasibility_oracle` 更新 RHS 并读取对偶，
`CutSession.step` 每次只执行一轮 MP→SP→加割/停止。

## 两张逐步切割图

图1横轴总负荷、纵轴预算。灰线为216个固定建设方案独立树上LP得到的完整验证前沿；
蓝线为截至当前全部割在整数建设集合上的投影外界，橙线为最近一次加割前的外界。
独立验证前沿不参与 Benders 候选选择或割生成。

图2默认比较20,000、30,000、40,000元和无建设预算上限，块1的`BUDGETS`可修改，`None`表示无预算上限。
四个面板使用相同坐标范围，均保留完整配变有功上限142.5 kW、线路容量和电压约束。
每条割对每个建设方案分别裁剪；按预算筛选方案后，显示这些多面体的**非凸并集**。
绘图逐面扣除内部重叠，不取跨方案整体凸包；灰线保留最近一次裁剪前边界，橙色标出最近割的外边界片。
当前 `x` 下累计割的 `g_min/g_max`，在 $p\ge0,\sum_i p_i\le142.5$ 的单纯形上解析计算。

| 建设预算 | 纳入方案数 | 最大总负荷 |
|---|---:|---:|
| 20,000元 | 17 | 100 kW |
| 30,000元 | 53 | 100 kW |
| 40,000元 | 105 | 135 kW |
| 不设上限 | 216 | 142.5 kW |

20,000与30,000元的最大总量相同，后者的节点分配域仍明显扩大；三维域比单个总量最优值包含更多信息。

完整流程先完成向量 MP1，再通过“MP2→总量 MP1→预算减20元”恢复全部二维台阶。
随后对四个面板共同需要的216个合法建设方案的割外近似顶点执行固定设计 MP1/SP 检查。
候选顶点仅来自当前外近似；不读取独立物理真值。某个固定设计的所有顶点均通过 SP，
即可由凸性证明其整个多面体可行；所有预算内设计完成后，并集域才具有完整性证书。
单个 MP1 查询或单次最大总负荷查询的收敛，不能作为整个三维域的收敛证据。
