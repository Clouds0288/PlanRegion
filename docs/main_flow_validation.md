# 主线重构与 SOCP 验证

日期：2026-09-27。Python 3.13.13 环境 `methods`，Gurobi 13.0.2，数值运行使用单线程。

## 调试入口

主循环位于 `main.build_continuous_region`，五步注释就在分支旁：

1. **方向 MP2 初始化。** 对每个坐标最大化负荷，其他负荷自由，再最大化总负荷。全局上界限定本预算外域，可行解按完整网架 `x` 加入内域。二维共 3 次，三维共 4 次。
2. **选择点和网架。** 普通候选取已知网架收缩外域中未被内域并集覆盖的顶点，按实际 kW 总量最大优先。全局搜索若返回内部见证，则先补齐同网架的支撑点。
3. **全局剩余域搜索。** 普通候选耗尽，或完成活动见证且累计 96 次 SP 后调用。`x,p` 同时自由，不限于已知网架；返回新的网架与见证，或给出全局覆盖证明。
4. **一次 SP 与区域更新。** 固定选中的 `x,p`。可行点只扩大自己的网架内域；联合割保存一次，并代入各网架 `x` 更新外域。某方案失败不会直接删除所有方案下的同一个负荷点。
5. **结束与汇总。** 仅凭已证空域或全局覆盖证书结束。默认入口只构造 SOCP 域，全部构域完成后再进行 AC 核查。

已删除主线默认 MP1、旧的 `seeds/queue/pending/seed` 调度、`RegionState.next_point` 和 `evaluation_bounds`。模型层负责一次优化，几何层负责集合操作，下一步的选择集中在主循环中。

步骤日志不再重复保存运行向量 `state` 和 `answer` 内的割；割只在割事件保存。三维结果去掉道路/型号参数副本、容量统计和容差字典，保留网架标识、预算、归一化箱、精度、内外域、认证状态、次数和耗时。

SP 直接最小化原始 `eta`，固定使用 `Aggregate=0`、`ScaleFlag=0`、`BarQCPConvTol=1e-9`。物理接受阈值仍为 `PLANNING_TOL=1e-8`；保留求解状态、原始残差、有效割及全局覆盖的数学检查。没有新增重试、替代求解器或答案修补。
