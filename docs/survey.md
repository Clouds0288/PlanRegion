# 道路勘察与规划域

五节点案例的物理参数统一定义在 `Network/concept5.py`。当前正式入口 `survey.py` 使用恢复后的对偶主线，建设预算为 4，负荷轴是节点 1、2 的有功 p₁、p₂，单位 kW。

确认域只允许使用已知可用道路，乐观域允许使用所有尚未证实不可用的道路。两者都允许在建设预算内选择拓扑和型号，每个负荷点可以由不同建设方案支撑；不同方案之间取并集。

每一轮对未知道路 α 分别计算：

- 可用时，确认域增加的面积 ΔS⁺。
- 不可用时，乐观域排除的面积 ΔS⁻。

条件边际价值为 V = πΔS⁺ + (1−π)ΔS⁻，按 V / 勘察费选择下一条道路。面积增量、信息价值及其数值上下界的原字段均保留。观测只在选择之后读取，不提前进入评分。

`DomainCache` 按道路允许集合缓存区域。同一物理模型和评价箱下的联合割可跨集合复用，道路掩码只进入主问题。每次不必从头计算已有状态，也不预枚举全部建设方案。新查询仍使用 MP2 → MP1 → SP 与剩余域认证。

停止时同时要求剩余单路价值上界和整个确认/乐观信息间隙上界不超过 5 kW²。求域的数值面积区间另要求不超过 0.5 kW²；信息不确定性与求解误差不混用。

## 运行与结果

```text
python survey.py --threads 1
python survey_plot.py --results results/concept5/<本次时间戳>
```

每次运行新建结果目录，包含协议及源文件指纹、逐轮区域、全部候选评分、共享割和独立 AC 点核查。非凸见证重新从本次发现的方案生成，`plan_a`、`plan_b` 对应本次 `schemes.json` 的编号；不得用它们索引旧枚举表。

默认合成观测是 A/C/E 可用、B/D 不可用，F 未赋真值。预期序列为 A+ → B− → E+ → D− → C+，F 不再勘察。测试中单独保存冻结参考数据，仅用于检验重构没有改变结果，正式入口不读取它。

图中绿色代表本轮新增，红色斜线代表本轮删除；已勘察道路的价值轨迹结束，不补成零。独立 AC 顶点检查只能说明已检验点的可行性，图中连续域仍称 SOCP 规划域。
