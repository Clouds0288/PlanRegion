# FourBus 3D 正负功率：支持面新方案与当前主线

本次实测中，主线的可行内域更完整；新方案完成认证的符号分区更多、外包络更紧，但混合正负分区仍有数值稳定性和查漏耗时问题。两者均未取得完整三维域的全局覆盖证书，不能以 89 秒与 271 秒直接声称新方案加速约 3 倍。

## 配置与评价口径

- FourBus 节点 `(1,2,3)`，`mode=1`，预算 20000，负荷 PF=0.95、光伏 PF=1。
- 两者均使用 20 个求解线程、总时限 300 秒、tau=0.005、GEOMETRY_TOL=1e-8、PLANNING_TOL=1e-8；剩余时间按剩余符号分区均分。
- 新方案仍是 light MILP 按需发现方案、候选点 SOCP 核验、固定方案支持面认证。没有建设方案枚举或 no-good 排除；遍历的 8 项是功率符号分区。
- 单次顺序运行，不是重复统计基准。耗时包含原生回放记录；新方案还包含分区结果保存开销。独立扫描及最终文件保存不计入构域耗时。
- 扫描复用项目已有的独立 SOCP 80×80×80 网格，共 512000 点，其中 184784 点可行。两种方法在完全相同的网格上评价，未用扫描结果构域。
- 网格范围为 `[-170,-135,-135]` 至 `[158,128,127]` kW。下表格点指标只适用于此范围，不代表网格外或连续域覆盖证明。

## 结果

| 指标 | 支持面新方案 | 当前主线 |
|---|---:|---:|
| 本次构域耗时 | 89.23 秒 | 271.02 秒 |
| 完成覆盖认证的符号分区 | 4/8 | 1/8 |
| 完整三维域全局认证 | 未完成 | 未完成 |
| 内域遗漏率：漏掉的可行格点 / 全部可行格点 | 16.2817% | 5.6628% |
| 内域遗漏格点 | 30086 | 10464 |
| 内域误收率：误收不可行格点 / 内域格点 | 0% | 0% |
| 外包络遗漏率 | 0% | 0% |
| 外包络误收率：多包的不可行格点 / 外包络格点 | 35.3667% | 44.4883% |
| 全局初始化 MP2 | 32 | 32 |
| 固定方案支持求解 | 1292 | 不适用 |
| 候选/顶点 SP | 404 | 2208 |
| 射线求解 | 不适用 | 1954 |
| 全局查漏 | 409 次 light MILP | 120 次 physical MISOCP |

不同类型的求解不能简单相加作为等价工作量。新方案记录了 41 个“方案—符号分区”组合，跨分区去重后为 12 个建设方案；枚举调用次数为 0。

## 分区停止原因

| 符号分区 | 新方案 | 主线 |
|---|---|---|
| +++ | 已认证 | 时限 |
| ++- | light 查漏时限 | 时限 |
| +-+ | 候选 SP 返回 status=13，未获证 | 时限 |
| +-- | 已认证 | 时限 |
| -++ | 候选 SP 返回 status=13，未获证 | 时限 |
| -+- | 候选 SP 返回 status=13，未获证 | 时限 |
| --+ | 已认证 | 时限 |
| --- | 已认证 | 已认证 |

没有通过放宽容差、切换失败后的数值参数或忽略异常来宣称成功。新方案的较短总耗时包含三个数值未决分区的提前停止，完成度与主线不同。

## 校验与可复现文件

- 20 项测试通过：符号契约、原二维回归、三维扩张几何、8 个符号分区的物理支持见证、三维当前面认证。
- 新方案保存的 882 个物理见证全部经原约束再次代入检查，最大违反量 `1.5389e-10`，低于 `1e-8`。
- `protocol.json` 保存运行设置及源码 SHA-256；比较结束确认源码未变化。
- `comparison.json` 保存两种方法的原始结果、扫描指标、分区认证状态、扫描文件 SHA-256 和见证审计。
- `support_1/partition_*.json` 保存新方案支持面、支持上下界、全局查漏与停止证据。
- 两种方法各有 `monitor.json.gz` 原生过程回放，支持 monitor.py 的双窗口比较。
